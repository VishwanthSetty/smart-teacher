# Teacher & Student Features

**Date:** 2026-09-11
**Scope:** Only what a `TEACHER` or `STUDENT` account can reach. School-admin and platform (super-admin) capabilities are deliberately excluded.

Source of truth for access: `apps/api/test/rbac-matrix.e2e-spec.ts` (`MATRIX`), `apps/web/src/lib/nav.ts`, and `apps/api/src/entitlements/actor-content-scope.service.ts`. Anything not listed here is not reachable by these two roles today.

## 1. Account & session

| Feature | Teacher | Student | Where |
| --- | --- | --- | --- |
| Log in with school email + password | ✅ | ✅ | `POST /auth/login`, `/login` |
| Set initial password from an invite link | ✅ | ✅ | `GET /auth/invite`, `POST /auth/set-password`, `/set-password` |
| Forgot password (email link, 1-hour single-use token) | ✅ | ✅ | `POST /auth/forgot-password`, `/forgot-password` |
| Reset password from the emailed link | ✅ | ✅ | `POST /auth/reset-password`, `/reset-password` |
| Log out (this device only, other devices stay signed in) | ✅ | ✅ | `POST /auth/logout` |
| View own profile (`GET /users/me`) | ✅ | ✅ | Used by the dashboard shell / avatar menu |
| Stay signed in across ~30 days without re-login | ✅ | ✅ | Refresh-token rotation in `middleware.ts` |

**Notes**

- The browser never holds a JWT. Tokens live in httpOnly cookies set by the Next.js BFF (`apps/web/src/app/api/auth/*`).
- Teachers and students can be created by a School Admin **with an admin-issued password** (`Amber-Fox-4821` style, generated by `PasswordsService`) instead of an email invite — useful for students without mailboxes. The admin can view/reset that password; the teacher or student simply logs in with it.
- Resetting a password revokes every live session immediately (`PASSWORD_RESET`), not at the next token expiry.
- Disabling an account or suspending the school takes effect within one access-token lifetime (~15 minutes), because both are re-checked on every refresh.
- Login is throttled: 20 failures in 50 minutes locks the email (per school) or the IP with a `429`. Password-reset requests are limited separately (5/hour).

**Playback security (applies identically to both roles):** every play request re-runs the entitlement chain via `VideosService.findPlayableVisibleTo` before minting a short-lived ES256 JWT scoped to `videos/<id>/`. Tokens last at most ten minutes; media URLs are useless without one. Signing keys exist only in the API — the edge worker can verify, never mint.

| Feature | Detail | Route / page |
| --- | --- | --- |

> **Known breadth:** teacher roster and section reads are tenant-scoped, not assignment-scoped — a teacher sees every student and section in **their own school**, not only their own classes. Cross-tenant reads are impossible. Narrowing this to assigned sections is an open follow-up.

## 4. What each role actually sees — content scope rules

`ActorContentScopeService.resolve()` is the single answer to "which curricula may this actor reach?", and every list read, single-item read, and playback mint derives from it, so a detail view can never be wider than the list.

### Student

1. Start from the school's **published** entitlements.
2. Keep only curricula whose `audience` is `STUDENT`.
3. Keep only curricula matching the grade level of their **active enrollment**.
4. **No active enrollment → empty library.** This fails closed deliberately: an unplaced student must not inherit the whole school library.

A student therefore sees exactly one grade's student-facing subjects, and never teacher-facing material.

### Teacher

1. Start from the school's **published** entitlements.
2. **No grade-bearing assignment yet → the full school entitlement set.** Lenient by design, so an admin who hasn't backfilled assignments doesn't blank every teacher's library.
3. **Once any assignment exists:** every `TEACHER`-audience curriculum stays reachable, and `STUDENT`-audience curricula are narrowed to the `(gradeLevel, subject)` pairs they actually teach.

So a teacher gets their own teaching material plus the student material for their own classes — and can preview exactly what their students see via the audience toggle.

### Shared guarantees

- Everything is tenant-scoped automatically by `prisma/tenant-guard.extension.ts` — no handler remembers to filter by school.
- A curriculum the school is not entitled to, or that belongs to another school's tenant, returns **404 — never 403**. Existence is never leaked.
- Entitlement is granted at the **curriculum** level (the whole grade × subject tree); there is no per-video or per-chapter licensing.

## 5. Explicitly NOT available to teachers or students

The RBAC suite asserts this directly (`denies TEACHER and STUDENT every admin endpoint`).

- **Every `/admin/*` route** — user management, school management, video/document authoring and upload, grade-level and subject taxonomy, curriculum schemas and content nodes, entitlement grants, platform stats.
- **Creating or editing content** of any kind. Authoring is `SUPER_ADMIN`-only; neither role can upload a video or a PDF.
- **Creating students, teachers, sections, or assignments** — School Admin only, including all bulk-CSV import routes under `/teachers/bulk/*` and `/students/bulk/*`.
- **Viewing or resetting anyone's password** (`GET|POST /teachers/:id/password`, `GET|POST /students/:id/password`) — School Admin only.
- **Resending invites** (`POST /users/:id/resend-invite`) — School Admin and above.
- **School settings**, entitlement views, platform settings.
- **Any cross-tenant read whatsoever.**

## 6. Not built yet (relevant to these roles)

Named here so the list isn't mistaken for a roadmap of existing behaviour:

- **Timetable / scheduling** — nav item and placeholder page only; no models, no API.
- **Watch progress, resume-where-you-left-off, completion tracking** — no progress model exists.
- **Assignments, homework, quizzes, grading** — none.
- **Search or filtering inside the school-facing library** — the `search` / `status` / `contentNodeId` query filters exist only on the `/admin/videos` authoring surface.
- **Messaging, announcements, notifications** — none.
- **Student-facing dashboard with stats** — students are redirected past `/dashboard` to their subject grid.
- **Teacher dashboard stat tiles** — the teacher branch of `/dashboard` is a placeholder panel.
- **Mobile app** — the API is Swagger-documented for it (`/api/docs`), but only the web client exists. See `docs/2026-08-10-mobile-app-feature-list.md`.
